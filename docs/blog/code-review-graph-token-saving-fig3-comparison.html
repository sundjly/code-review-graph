review 工作流对比：传统读文件 vs code-review-graph
传统方式

每次 review 都在重复劳动

  • 手动找相关文件，逐个传给 Claude
  • 大量无关代码进入上下文窗口
  • 每次推导调用关系，结构从头理解
  • 不知道影响范围，只能靠经验猜
  • 改动越大，context 越乱，越容易遗漏
  • 5,000–15,000 tokens / 次，大部分浪费
code-review-graph

结构预算好，查询给精华

  • get_minimal_context 一句，100 tokens 全局概览
  • detect_changes 精准定位受影响函数和调用链
  • 图谱预计算结构关系，查询不需要读文件
  • get_impact_radius BFS 定量扩散范围
  • ≤5 次 tool call，工作台始终干净
  • ≤800 tokens，节省 90%+，推理更聚焦
